# 控制链与接口

代码按 `main -> getmax1 -> choosekp/choosekd/choosea1/choosea2 -> getadcave -> vccla -> go` 运行。`getmax1` 需手动扫描赛道信号并按键确认，参数也通过板上按键确认；源码没有固定比赛时使用的最终参数记录。

## 数据与参数

| 项目 | 源码行为 |
| --- | --- |
| 传感输入 | `adc_once(8..11, ADC_12BIT)` 四路；对应库中的 `ADC_P00..ADC_P03` |
| 校准 | `Adc.max[4]` / `min[4]`，初始化为 0 / 4096，再按扫描值更新 |
| 归一化 | 每路重复五次：`(sample-min)/(max-min)*100`；累加器为 `long`，最后整除 5 |
| 误差 | `a1*(adcave[0]-adcave[3]) + a2*(adcave[1]-adcave[2])` |
| PD | `vc = kp*errornow + kd*(errornow-errorpre)`，没有显式采样周期 |
| 菜单默认值 | `kp=20, kd=2, a1=10, a2=5`，每次按键增减 1；默认值不是比赛最终参数 |
| 按键 | P3.4–P3.7 低电平有效，阻塞延时 60 ms；优先级 KEY0、KEY1、KEY2、KEY3 |
| 电机通道 | `fl=0x02, fr=0x12, bl=0x22, br=0x32`，对应 PWM1P_P20 到 PWM4P_P26 |
| PWM 初始化 | 四个 P 通道和四个 N 通道，频率参数 500；P 通道随后设为 5000 |

`goforward(v)` 四轮输出 `5000+1000*v`；`rightline(v)` 按前左/前右/后左/后右输出 `[5000+1000v, 5000-1000v, 5000-1000v, 5000+1000v]`。`turnmiddle(v)` 按 `[+, -, +, -]` 组合改变轮速。函数名表示课程中意图的运动方式，真实方向还依赖电机接线和轮子安装。

`go()` 采用另一组输出：`vc>0` 时减小左右布局中的左侧两个值，`vc<0` 时减小右侧两个值，另一侧设为 10000。代码没有完整的速度闭环或编码器反馈。

## 保留的历史限制

1. `main` 的自动局部 `Adc` 未整体清零。`adcinit()` 只初始化极值，`vccla()` 首次会读取尚未初始化的 `errornow`。主机测试明确先初始化测试结构体，因此不代表原固件首步行为已修复。
2. `go()` 的 `vc==0` 分支不写 PWM，保留之前的轮速；`rightslash`、`turnbehind`、`rightbehind` 也只写部分轮子。测试明确检查这种状态保留。
3. 运动函数和 `go()` 没有限幅。测试展示 `goforward(6)` 请求 11000；负数/越界浮点转 `uint16` 的结果不作跨平台保证，不应据此直接驱动设备。
4. `getadcave()` 每个接受周期调用两次 ADC，先判断的值与实际累计的值不同。合成测试让首次值为 400、第二次为 1200、校准上限为 1000，得到归一化结果 120，说明检查不能保证累计值位于校准范围内。
5. 持续大于最大值会重复 `j--`，没有超时；本轮用 stub 读取计数上限截断子进程，确认 256 次后仍未返回。最大值等于最小值没有除零保护，低于最小值也没有下限裁剪。
6. 浮点归一化逐步加到 `long` 会截断，小数均值也会被整除截断。输入 333、校准 0–1000 时测试结果为 33。
7. `getmax2()` 的 `int i` 每次加 0.6 后转回整数，不能按预期推进循环；该函数在现存 `main` 中被注释，测试不执行它。`turn(float r)` 仅声明，选定源码中没有定义，也未在当前入口调用。
8. 参数菜单和采样均为阻塞式，缺少稳定的采样周期、失线停车和异常恢复。现存源码不是可直接投用的安全控制器。

这些行为未在归档中修复，避免把后补实现与 2024 年团队成果混合。原源目录没有改动。

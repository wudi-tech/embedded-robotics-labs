# 本地验证记录

日期：2026-10-25。测试环境为 Windows、Python 3.14 和 GCC。复现入口为 [run_host_tests.py](../tests/run_host_tests.py)。

实际执行结果：主机编译和测试命令退出 0；正常子进程 285 个断言通过；持续超校准上限子进程按预期在第 257 次 ADC 调用中由 stub 以状态 42 截断（此前已返回 256 个读数）。编译出现两条原始未使用变量警告：`getmax1` 的 `i` 与 `main` 的 `i`，未隐藏或修改。

## 验证对象

| 检查 | 执行方式与结论 |
| --- | --- |
| 前进、平移、旋转、部分轮子写入 | 直接调用原 `type.c`，捕获对应通道与 uint16 PWM 参数，断言正常值及状态保留 |
| PD 与上一拍误差 | 两次调用原 `vccla`，核对加权误差、前拍保存与控制量 |
| 零误差和数值边界 | 验证零误差不写输出、`vc=2000` 可请求 0、`goforward(6)` 请求 11000 |
| 采样/归一化 | 使用合成 ADC 读数，检查 40 次调用、截断和两次采样不一致导致的越界归一化 |
| 超校准上限 | 单独子进程持续返回 1100，校准最大 1000；stub 用读取计数上限验证函数仍未返回，避免无限挂起 |
| 校准和按键 | 原极值初始化函数不清理误差状态；确认菜单默认值与按键优先级 |
| 主入口 | 原 `main.c` 仅在编译时重命名为 `archived_firmware_main` 生成 object，未调用其无限循环 |
| 来源 | 三个入选源码与原件逐字节 SHA-256 一致，原目录完整文件清单与归档前对比 |

## 主机适配差异

`tests/host/headfile.h` 是本轮新增的最小接口 stub，未从厂商实现复制代码。只声明应用所需的函数和常量；ADC 与 PWM 的通道值对应本地课程库枚举，PWM 参数保留 16 位无符号类型。PWM/OLED/延时与初始化均无硬件副作用，输入由测试控制。

测试没有复制 PD 或运动公式作为替代实现；参与运行的是哈希保持一致的原始 `type.c`。测试结构体先清零，不能消除原固件入口未初始化误差的问题。GCC 的 `int/long` 宽度、浮点计算、ABI 与 C51 不同，且没有设备寄存器、中断、真实 ADC 噪声、采样时间、马达动力学或电池模型。测试未调用菜单循环全路径、真实校准流程或所有历史函数，也不覆盖所有异常。

本轮未进行完整固件链接、烧录、整车仿真或实机测试。断言数量包括 stub API 的通道/分辨率检查，不能当作独立场景数或硬件验收项数。
